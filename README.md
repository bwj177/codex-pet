# Codex Pet

Codex Pet is a local desktop companion for Codex sessions. It runs as a macOS native transparent desktop pet, talks to a local runtime, and can launch Codex while showing safe, structured session/workspace metadata.

## Current Status

This project is currently a working MVP, not a packaged product.

- Native macOS desktop pet: implemented.
- Local runtime API: implemented.
- Global `codex-pet` launcher: implemented.
- Workspace/Git metadata: implemented.
- Codex CLI path/version metadata: implemented.
- Token/context usage: simulated until Codex exposes stable machine-readable usage events.
- Live2D model: not implemented yet.
- Multi-session isolation: not implemented yet.

## Quick Start

Start the desktop pet:

```bash
codex-pet --pet-only
```

Start Codex through the pet:

```bash
codex-pet
```

Pass Codex CLI arguments:

```bash
codex-pet --no-open exec "summarize this repo"
```

Open browser mode instead of the native desktop pet:

```bash
codex-pet --browser --pet-only
```

Show current runtime state:

```bash
codex-pet --status
```

## Desktop Pet Features

Implemented desktop behavior:

- macOS native AppKit/WebKit window.
- Transparent background.
- Borderless window.
- Floating always-on-top level.
- Can join all desktop spaces.
- Dragging the pet moves the native desktop window.
- Desktop mode is not a normal browser tab.

Implemented pet interactions:

- Mouse hover shows a speech bubble.
- Pet eyes follow the cursor.
- Click head area for a head-pat reaction.
- Double-click the pet to open the status panel.
- Press `p` to open the status panel.
- Press `Esc` to close the panel.
- Press `Esc` again when the panel is closed to exit the desktop pet.
- Pet has breathing, tail movement, eye tracking, and state-driven mood animations.

Implemented appearance customization:

- Built-in appearance editor in the status panel.
- Editable pet name, render mode, preset, body color, head color, accent color, outline color, scale, eye style, ears, and tail.
- Image mode can import a PNG, JPEG, WebP, or GIF role image and use it as the pet body.
- Image mode supports contain/cover fit, image scale, X/Y offset, and optional default 2D parts overlay.
- Built-in pet library currently includes CC0 animal assets from Kenney and OpenGameArt.
- Presets: Mochi, Terminal, Ember, and Cloud.
- Changes apply immediately to the desktop pet.
- Settings persist in the client via `localStorage`.
- Current skin can be copied as JSON for future package/import support.

Implemented status reactions:

- `idle`
- `thinking`
- `running_command`
- `success`
- `error`
- `waiting_user`
- high-context-pressure visual state, currently driven by simulated context usage

## Codex Launcher Features

The global `codex-pet` command:

- Starts the local runtime if it is not already running.
- Opens the native desktop pet window by default on macOS.
- Can launch Codex as a child process.
- Updates pet state when Codex starts, runs, exits successfully, or fails.
- Watches workspace metadata while Codex is running.
- Redacts likely prompt text by default.

## Appearance Customization

Open the status panel by double-clicking the pet or pressing `p`, then edit the `Appearance` section.

Current customizable fields:

- `name`: pet display name.
- `mode`: `procedural` for the built-in layered pet or `image` for an imported role image.
- `preset`: quick visual baseline.
- `body`, `head`, `accent`, `outline`: core palette.
- `scale`: visual size inside the desktop window.
- `eyes`: `round`, `calm`, or `spark`.
- `ears`: show or hide ears.
- `tail`: show or hide tail.
- `imageFit`: `contain` or `cover`.
- `imageScale`: imported image size.
- `imageOffsetX`, `imageOffsetY`: imported image position.
- `showParts`: overlay the default 2D pet parts on top of an imported image.

The current implementation has two render modes: a procedural layered 2D model driven by CSS variables, and a single-image role skin for imported character art.

Role image import:

- Use `Built-in Pet` to select an asset already bundled under `assets/pets`.
- Use `Role Image` in the `Appearance` section.
- Supported formats: PNG, JPEG, WebP, and GIF.
- Images are converted to a local Data URL and stored in the current skin JSON.
- Images larger than about 2.8 MB are rejected to avoid exhausting browser or WebView local storage.
- Imported images stay local to this client; they are not uploaded.
- Importing an image switches `mode` to `image` and hides the default parts by default.

Bundled asset library:

- Runtime manifest: `assets/pets/library.json`.
- Source notes: `assets/pets/README.md`.
- Kenney Animal Pack: CC0, bundled from `PNG/Round (outline)`.
- OpenGameArt 2D cat sprite: CC0.

Storage details:

- Local storage key: `codex-pet.skin.v1`.
- Scope: per WebView or browser client.
- Reset returns the current client to the default Mochi skin.
- Copy JSON copies the current skin object for debugging or future import/export work.

The next visual upgrade path is to keep this editor as the user-facing control surface, then add automatic background removal, multi-layer image packages, and finally Spine or Live2D when motion quality becomes the main constraint.

## Metadata And Privacy

Default disclosure mode is `standard`.

In standard mode, Codex Pet shows structured metadata but does not show:

- Prompt text.
- Full user messages.
- Environment variables.
- Secrets or tokens.
- Full diffs.
- File contents.
- Full command arguments that are likely to contain prompt text.

For example, this:

```bash
codex-pet --no-open exec "summarize this repo"
```

is displayed as:

```text
codex exec [prompt redacted]
```

Use verbose mode only when you explicitly want command arguments visible:

```bash
codex-pet --privacy=verbose --no-open exec "summarize this repo"
```

Token and context usage are intentionally marked as simulated for now. They should not be treated as real Codex usage accounting until a stable Codex usage event source is integrated.

## Runtime API

The local runtime serves the UI and state API on:

```text
http://127.0.0.1:4177
```

Endpoints:

```text
GET  /api/state
POST /api/state
GET  /events
```

Example update:

```bash
curl -X POST http://127.0.0.1:4177/api/state \
  -H 'content-type: application/json' \
  -d '{"status":"running_command","summary":"Running checks","command":"npm test"}'
```

Browser-side API:

```js
window.codexPet.update({
  status: "running_command",
  contextUsage: 0.68,
  tokens: 34000,
  summary: "Running project verification.",
  command: "npm run test",
  changedFiles: ["src/main.js"]
});
```

## Pet Package Contract

`pet-package.example.json` sketches the future package format for skins and advanced models:

- Renderer assets: layered 2D now, Live2D `model3.json` later.
- Behavior rules: status-driven motion, expression, badge, and speech.
- Hit areas: head/body/tail interactions that map pointer events to actions.

The current renderer is a dependency-free layered 2D implementation. The intended long-term renderer interface is:

```ts
interface PetModel {
  play(animation: string): void;
  setMood(mood: string): void;
  lookAt(x: number, y: number): void;
}
```

## Roadmap

High-priority pending work:

- Multi-session isolation: store state under `runtime/sessions/{sessionId}.json` instead of one global state file.
- True Codex token/context integration when Codex exposes stable machine-readable events.
- System tray/menu bar controls: show, hide, quit, open status, restart runtime.
- Persistent pet/window settings: last position, panel preference, personality.
- Better desktop interaction: snap-to-edge, screen bounds handling, idle roaming, click-through modes.
- Skin import/export and user skin package loading beyond local Data URL images.
- App packaging as a `.app` bundle with icon and launch services metadata.

Modeling and visual roadmap:

- Add automatic background removal for imported character images.
- Add image-layer skins that map editor fields to replaceable body/head/accessory assets.
- Replace or supplement layered 2D with Live2D via PixiJS/Cubism.
- Add skin package loading from `pet-package.example.json`.
- Add expression/motion priority rules, cooldowns, and behavior composition.
- Add richer state animations for tests, failures, approvals, and context pressure.

Safety roadmap:

- Keep prompt text redacted by default.
- Add configurable disclosure levels per field.
- Add secret scanning before displaying any future command/log/diff content.
- Avoid showing full diffs or file contents unless explicitly enabled.

Cross-platform roadmap:

- macOS is implemented first.
- Windows/Linux desktop shells are not implemented yet.
- Browser mode remains available for debugging and non-macOS fallback.
